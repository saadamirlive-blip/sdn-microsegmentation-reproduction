## 3. Discrepancy analysis (task brief §33)

### CR 95.6 % vs 96.8 % (−1.2 pp) — PASS
The shortfall is almost entirely the **6 % "hit-and-run" fraction** of attack flows
that complete inside a single 3.0 s telemetry window and are therefore uncatchable
by 3 s polling — a limitation the paper itself names (Sec IV.E, "bound being the
3.0 second telemetry polling delay"). Increasing/removing that fraction moves CR to
~99 % / ~96 %; it is left at a mechanism-justified 6 % and **not tuned** to hit 96.8.

### T_resp 2.47 s vs 2.30 s (+0.17 s) — PASS
`T_resp = polling_wait (mean 1.5 s) + extraction (~0.30 s) + install (~0.55 s)`.
The paper's 2.30 s implies a slightly smaller polling-wait mean and/or install
time; the decomposition (ASSUMPTIONS §18) is a documented estimate, not fitted.

### FPR 0.38 % vs 1.2 % and FCR 0.31 % vs 1.5 % — INVESTIGATE
Root cause: **the paper specifies distributions for only 2 of the 6 features**
(`pps`, `bps`). The frozen assumptions for `duration` and the protocol ratios
(ASSUMPTIONS §6) plus the paper's own overlap mechanisms (iPerf3 bursts, Sec VI.B.7;
stealthy low-rate, Sec VI.B.4) produce classes that are **slightly more separable**
than the paper's live Mininet/Scapy/iPerf3 emulation. Consequences:
* offline FPR 0.16 % vs 0.20 % (already low);
* system FPR 0.38 % — correctly *higher* than offline (the runtime burst fraction
  is larger than the training one, per Sec VI.B.7), but still below 1.2 %;
* FCR tracks FPR (a benign flow is falsely contained only when it is both
  RF-misclassified and on a host that reached the Suspected/Compromised state).

To reproduce 1.2 % / 1.5 % exactly we would have to hand-shape the four
unspecified feature distributions until the classifier degraded to the paper's
operating point — i.e. reverse-engineer the target. Per §33 this is **not done**;
the gap is reported instead. The *direction and mechanism* (system FPR > offline
FPR, driven by runtime bursts; FCR ≳ FPR) are reproduced.

### NA 99.65 % vs 98.5 % (+1.15 pp) — PASS-ish
NA is `100 − persistent_loss − transient_loss`. `persistent_loss` is driven by FCR,
which is low here (§ above), so steady-state NA sits ~1 pp above the paper.
The *timeline shape* (Fig 7: dip at t=60/120 s, fast recovery above the 95 % SLA)
is reproduced — see `figures/fig07_availability_timeline.png`.

### Per-vector CR (Table VII) — mostly INVESTIGATE, within a few pp
Reproduced CRs cluster at 95 % ± 1 (paper spread 90–99 %). Ordering is roughly
right (HTTP-flood lowest). The paper's wider spread comes from vector-specific
detection differences its (unspecified) per-feature model would encode; ours are
governed mainly by the uniform hit-and-run fraction.

### Baselines (Table VIII) — INVESTIGATE
Latencies reproduce **exactly** (they are `[PAPER]` inputs: 45.0 / 30.0 / 15.0 s;
only symmetric zero-mean jitter is added). CR/FPR/FCR/NA are **mechanism
reconstructions** (ASSUMPTIONS §17) because the paper gives no baseline model:

| System | CR paper→repro | FPR paper→repro | FCR paper→repro | NA paper→repro |
|---|---|---|---|---|
| Traditional Firewall | 72 → 63.4 | 12 → 12.0 | 10 → 12.0 | 88 → 83.3 |
| IDS/IPS | 78.5 → 70.4 | 8.5 → 7.5 | 6.5 → 7.5 | 91 → 88.8 |
| Static SDN | 85 → 87.0 | 5.0 → 0.4 | 4.0 → 0.4 | 94 → 98.6 |

Static-SDN FPR/FCR are far below the paper because our Static SDN reuses the *same*
6-D Random Forest (per the Wainwright base paper); the paper's Static SDN evidently
used a less precise classifier. Firewall/IDS CR is ~8 pp low because our detection
model never credits containment for the horizontal-probe traffic (zero east-west
visibility) and applies vector-specific miss rates.

### Qualitative conclusions that DO reproduce
* Proposed system dominates all three baselines on all five axes (Fig 13/14).
* Multi-tier enforcement keeps NA above the 95 % SLA where firewall (83–88 %) and
  IDS (89–91 %) fall below it.
* Response latency is cut ~19–20× vs the firewall (47 s → 2.5 s), matching the
  paper's "94.9 % latency reduction" claim (ours: 94.8 %).
* Controller load and TCAM usage stay well inside Constraints 1–3.
